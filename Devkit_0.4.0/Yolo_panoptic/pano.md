# このプロジェクトは何をしているの?(はじめての方向け解説)

> 技術的な詳細・作業ログは [README.md](README.md)、起動コマンドだけ知りたい場合は
> [start.md](start.md) を参照してください。このページは「そもそも何をやっているのか」を
> 専門用語なしでざっくり理解するためのものです。

---

## 1. 一言でいうと

**USBカメラの映像を見て、「壁」「床」「ドア」がどこにあるか、そして「人」「椅子」「テレビ」
のような物がどこにあるかを、リアルタイムで色分けして表示するプログラム**です。

最終的には、`SiMa.ai Modalix`という小型のAI専用チップ(スマホより小さい基板)の上で
動かすことを目標にしています。パソコンではなく、電力もサイズも小さい組み込み機器の上で
AI画像認識を動かす、という点がこのプロジェクトの挑戦です。

イメージ図:

```
   カメラ映像
      │
      ▼
 ┌─────────────────┐
 │ ここに壁がある     │  ← 「領域」を塗り分ける(壁=青、床=緑、ドア=オレンジ…)
 │ ここに床がある     │
 │ ここに人がいる ○   │  ← 「物」を1つ1つ検出して枠と名前を付ける
 │ ここに椅子がある ○ │
 └─────────────────┘
      │
      ▼
  色分けされた映像を配信
```

このように、「面」で塗り分けるもの(壁・床・天井・ドア)と、「個体」として検出するもの
(人・椅子・テレビなど)を**両方同時に**認識する技術を、専門用語で
**パノプティックセグメンテーション**と呼びます。

---

## 2. なぜ2つのAIモデルを組み合わせているの?

世の中でよく使われている物体検出AI「YOLO」は、人や椅子などの**物**を検出するのは得意ですが、
壁や床のような**面**を認識するようには作られていません。

そこで、このプロジェクトでは2つのAIモデルを組み合わせています。

| 役割 | 使っているAI | やること |
|---|---|---|
| 物を見つける係 | YOLO11(既製品) | 「そこに人がいる」「そこに椅子がある」を検出 |
| 面を塗り分ける係 | 自作の軽量モデル | 「そこは壁」「そこは床」「そこはドア」を判定 |

「面を塗り分ける係」は、最初から自分たちで作ったわけではありません。まず**とても賢いが
とても重い(遅い)お手本AI**(1枚の処理に4秒以上かかる)に部屋の写真をたくさん見せて
「正解」を作ってもらい、その正解を真似するように**軽くて速い生徒AI**を訓練しました
(これを機械学習の世界では「蒸留」と呼びます)。結果、**お手本より約70倍速い**のに
ほぼ同じ精度のモデルができました。

最後に、この2つのAIの答えを1枚の絵に合成します。ルールはシンプルで、
「まず自信度の高い物(人・椅子など)から順番に置いていき、残ったすき間を壁・床・ドアで埋める」
という方式です。

## 3. 開発中に何が起きたか(つまずきと解決)

小さなAIチップの上でAIモデルを動かすには、パソコン上で動くAIモデルをそのまま持ってくる
だけではダメで、いくつもの変換・調整作業が必要でした。主なものを紹介します。

### つまずき1: 遅すぎる・重すぎる

最初にお手本にした高精度AIは1枚4秒以上かかり、とても「リアルタイム」とは言えませんでした。
→ 上記の通り、軽量な生徒モデルを訓練することで解決(**70倍高速化**)。

### つまずき2: チップに載せるには「軽量化」が必要

AI専用チップは、通常のパソコンのCPUと違い、計算を大幅に簡略化した数値表現
(小数点を使わない「整数」に近い形、いわゆる**量子化**)でしか計算できません。
これは電力・速度を稼ぐためのトレードオフです。量子化すると精度が少し落ちるのですが、
実測してみたところ劣化はごくわずか(精度指標で0.879→0.863、約1.8%の低下)で
済みました。

### つまずき3: モデルの一部がチップに対応していなかった

YOLOモデルの内部には「注意機構(attention)」と呼ばれる、複雑な計算を行う部品が
含まれています。ところが今回使うAIチップは、この部品の計算方法をそのままでは
実行できないことが分かりました。無理に動かそうとすると、モデルが3つのバラバラな
断片に分割されてしまい、実機で動かそうとした瞬間に**起動エラーで止まる**という
問題が発生しました。

これは実際にチップ上で動かしてみて初めて発覚した問題で、机上の検証だけでは
気づけませんでした。解決策として、その部品の計算式を「同じ答えを返すけれど、
チップが理解できる別の書き方」に書き換えることで解消しました。数式としては
完全に同じ意味なので、精度が落ちる心配もありません。この修正により、
バラバラだった3つの断片が1つにまとまり、無事にチップ上で動くようになりました。

### つまずき4: 実際にカメラをつないだら遅すぎた

すべての部品を実機に載せて動かしてみたところ、**1秒間に1.8枚**しか処理できませんでした
(人の目には「カクカクした紙芝居」のように見える速度です)。

原因を1つ1つ計測してみると、意外なことにAIチップ自体の計算(推論)はとても速く
(1回20ミリ秒程度)、遅さの正体は**それ以外の付随的な画像処理**(色を塗る、
拡大する、といった一見軽そうな処理)にあることが分かりました。組み込み機器の
CPUは非力なので、フルサイズの映像(1280×720ピクセル)に対して何度も同じような
処理を繰り返すと、それだけで数百ミリ秒かかってしまっていたのです。

そこで、次のような工夫で高速化しました:
- 色塗り・合成の計算を、映像を一旦小さく縮小してから行い、最後に1回だけ元のサイズへ
  拡大し直す(小さい画像なら計算量も少なくて済む)
- AIの生の出力から「本当に確信度の高そうな候補」だけを先に絞り込み、重い計算
  (確率への変換)は最後に残った少数の候補だけに行う

これらの工夫により、**1秒間に1.8枚 → 約6.9枚**まで、およそ3.8倍高速化しました。

## 4. 今、何ができるようになったか

- 実際のUSBカメラ映像を使って、AIチップ上で最初から最後まで動作することを確認済み
- 実際に人・机上の物などを検出し、壁・床の領域も塗り分けられることを画像で確認済み
  (ただし、物の名前が多少ズレることがあります。例:上着を「犬」と誤認識、
  ノートPCの角を「マウス」と誤認識、など。これは今回使っているAIが
  ネット上の一般的な画像で学習したもので、今回のような近距離・特殊な角度の
  被写体は少し苦手にしているためです。輪郭(どこからどこまでが1つの物か)は
  おおむね正確です)
- 処理速度は約6.9fps(1秒間に約6.9枚処理、1280×720サイズ)

## 5. これからやること

- さらなる高速化の余地あり(2つのAIの計算を同時並行に進める、など)
- 「壁・床・ドア」を判定するAIの学習データが今のところ「廊下」の写真しかないため、
  家具のある部屋の写真も追加して精度を確認する
- 詳しい残課題は [README.md](README.md) の「次の工程」を参照

## 6. 動かしてみるには

コマンドの実行方法は [start.md](start.md) にまとめてあります。ざっくり言うと:

1. `probe_camera.py` でUSBカメラを見つける(初回だけ)
2. `main.py` を実行する
3. 表示された案内コマンドを別のパソコンで実行すると、色分けされた映像が見られる

## 7. かんたん用語集

| 用語 | かんたんな意味 |
|---|---|
| YOLO | 写真から「何が」「どこに」写っているかを検出する、有名なAIの種類 |
| パノプティックセグメンテーション | 「面」の塗り分けと「物」の検出を両方いっぺんに行う認識方式 |
| 量子化(INT8) | AIチップの上で高速に計算できるよう、数値の精度を簡略化すること。省電力・高速化とのトレードオフで多少精度が落ちる |
| 蒸留 | 重くて賢いAIの「答え方」を、軽くて速いAIに真似させて学習させる手法 |
| MLA | このAIチップの中で実際にAI計算を行う専用回路の名前 |
| fps | 1秒間に何枚の画像を処理・表示できるかを表す数値。数字が大きいほど滑らかに見える |
| ONNX | 異なるAIツール間でモデルをやり取りするための共通ファイル形式 |
